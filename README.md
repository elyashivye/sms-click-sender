# SMS Click Sender

שליחת SMS מותאם אישית לרשימת אנשי קשר, דרך טלפון אנדרואיד המחובר בכבל USB -
**ישירות מהדפדפן**, בלי שרת, בלי Python, בלי `adb` מותקן מראש. אותו קוד בדיוק
עובד גם כ**אתר** (אפשר לארח בכל שירות אחסון, כולל הוסטינגר) וגם כ**תוכנה
להורדה** למחשב.

## איך זה עובד

הדפדפן (Chrome/Edge) מדבר עם הטלפון ישירות דרך **WebUSB**, באמצעות מימוש
מלא של פרוטוקול ADB ב-JavaScript (ספריות [Tango ADB](https://github.com/yume-chan/ya-webadb)).
לכל איש קשר, המערכת פותחת את מסך כתיבת ה-SMS בטלפון עם המספר וההודעה כבר
ממולאים, מאתרת אוטומטית את כפתור "שלח" על המסך (על ידי קריאת מבנה המסך
בזמן אמת - לא קואורדינטות קבועות), ומדמה הקשה עליו.

**שום דבר לא נשלח לשום שרת** - הקובץ, ההודעה, והתקשורת עם הטלפון, כולם
קורים מקומית בטאב הדפדפן (או בחלון של תוכנת ה-Desktop).

## דרישות

- דפדפן מבוסס **Chromium בלבד**: Chrome, Edge או Opera. **לא** Firefox
  ו**לא** Safari - הם לא תומכים ב-WebUSB.
- **HTTPS** (או `localhost`) - WebUSB לא עובד ב-http:// רגיל מכתובת מרוחקת.
- טלפון אנדרואיד עם **ניפוי USB (USB Debugging)** מופעל (הגדרות → אודות
  הטלפון → הקש 7 פעמים על "מספר build" כדי לחשוף "אפשרויות למפתחים", ואז
  הפעל שם "ניפוי USB")
- כבל USB בין הטלפון למחשב
- Node.js 18+ רק כדי **לבנות**/**לפתח** את הפרויקט (למשתמש הסופי באתר לא
  צריך Node בכלל - זה HTML/JS רגיל)

## הרצה מקומית לפיתוח

```
npm install
npm run dev
```
ופותחים את הכתובת שמודפסת (בד"כ http://localhost:5173).

## פריסה כאתר (כולל הוסטינגר)

```
npm run build
```
זה יוצר תיקיית `dist/` עם קבצים סטטיים בלבד (HTML/CSS/JS) - **בלי** תלות
בשרת מכל סוג. מעלים את תוכן `dist/` לכל שירות אחסון סטטי (הוסטינגר, GitHub
Pages, Netlify, Cloudflare Pages וכו').

חשוב: השירות חייב להגיש את הקבצים דרך **HTTPS** (רוב שירותי האחסון,
כולל הוסטינגר, נותנים SSL חינמי כברירת מחדל). כל מי שנכנס לאתר עם Chrome
ומחבר טלפון **למחשב שלו** יכול להשתמש בו - אין צורך בהרשאות/סיסמה, כי
אין שרת שמחזיק מידע או ניגש לטלפון של אף אחד מרחוק.

## בניית תוכנה להורדה (Desktop, Electron)

אותו קוד בדיוק, עטוף בחלון עצמאי (Electron - אותה טכנולוגיה שעליה בנויים
Slack/Discord/VS Code) כדי שאפשר יהיה להוריד קובץ, להתקין, ולהשתמש בלי
לפתוח דפדפן/אתר בכלל.

פיתוח/בדיקה:
```
npm run electron:dev
```

בניית קובץ התקנה (Windows/.exe, Mac/.dmg, Linux/.AppImage - כל אחד נבנה
על המערכת המתאימה לו):
```
npm run electron:build
```
התוצאה תופיע בתיקיית `release/`.

## הרשאות USB בלינוקס (דפדפן או תוכנת ה-Desktop)

ב-Linux, גם דפדפן/Electron צריכים הרשאת מערכת הפעלה כדי לגשת ישירות
להתקן USB (לא משנה שזה WebUSB ולא `adb` נפרד - ההרשאה היא ברמת ה-USB
עצמו). ראו `deploy/51-android-usb.rules` בפרויקט הזה:

1. מצאו את ה-Vendor ID של הטלפון: `lsusb`
2. העתיקו את `deploy/51-android-usb.rules` ל-`/etc/udev/rules.d/`
   (ועדכנו בו את ה-Vendor ID אם צריך)
3. `sudo udevadm control --reload-rules && sudo udevadm trigger`
4. נתקו וחברו את הטלפון מחדש

## הרשאות USB ב-Windows

לפעמים ב-Windows הדרייבר שכבר מותקן לממשק ה-ADB "תופס" אותו ומונע
מ-Chrome/Electron לגשת אליו ישירות. אם לחיצה על "התחבר לטלפון" לא מציגה
את הטלפון ברשימה, יש להחליף את הדרייבר של ממשק ה-ADB (לא של כל הטלפון!)
ל-**WinUSB** בעזרת הכלי החינמי [Zadig](https://zadig.akeo.ie/).

## שימוש באפליקציה

1. **חיבור הטלפון** - לחצו "התחבר לטלפון". יופיע חלון בחירת התקן של
   הדפדפן - בחרו את הטלפון. בפעם הראשונה תופיע בטלפון בקשת "לאפשר ניפוי
   USB?" - יש לאשר אותה פיזית על מסך הטלפון (אפשר לסמן "אפשר תמיד ממחשב
   זה" כדי לא לחזור על זה).
2. **קובץ אנשי קשר** - בחרו קובץ `.xlsx`/`.xls`/`.csv`. כל עמודה בקובץ
   (לדוגמה "שם", "טלפון", "עיר", "סכום"...) הופכת אוטומטית לפרמטר זמין.
   בחרו איזו עמודה היא מספר הטלפון (המערכת מנסה לנחש לפי שם העמודה).
3. **ההודעה** - כתבו את ההודעה, ולחצו על צ'יפים כמו `{שם}` כדי להוסיף
   פרמטר מכל עמודה בקובץ במקום הסמן.
4. **תצוגה מקדימה** - טבלה שמראה בדיוק מה יישלח לכל איש קשר (עד 20 שורות
   ראשונות), כולל אזהרה על פרמטר שלא קיים בקובץ (טעות הקלדה למשל).
5. **שליחה** - "מצב בדיקה" מסומן כברירת מחדל ומדמה את התהליך בלי לשלוח
   באמת. מבטלים את הסימון כדי לשלוח בפועל. יש הגבלת קצב (השהיה בין
   הודעות) כדי לא להעמיס על הטלפון ולא להיראות כספאם. חשוב שהמסך של
   הטלפון יישאר דלוק ולא נעול לאורך כל השליחה.

## מגבלות ידועות

- **רק דפדפנים מבוססי Chromium** (ולא בדפדפן נייד בכלל - זה פיצ'ר Desktop).
- שיטת "סימולציית ההקשה" תלויה במסך שהמכשיר לא נעול. אם המכשיר ננעל
  באמצע ריצה, ההודעות הבאות לא יישלחו (יופיע כישלון בטבלת התוצאות).
- אפליקציות SMS שונות (Google Messages, Samsung Messages וכו') עלולות
  להיראות שונה על המסך; יש שדה "קואורדינטות גיבוי ידניות" בהגדרות
  המתקדמות למקרה שהאיתור האוטומטי נכשל על מכשיר/אפליקציה מסוימת.
- חבילת `xlsx` (SheetJS) שבה משתמשים לקריאת הקבצים מסומנת ע"י `npm audit`
  עם חשיפת אבטחה ידועה (ללא תיקון זמין ב-npm) שרלוונטית בעיקר לפענוח
  קבצים ממקור לא מהימן על שרת משותף. כאן זה לא רלוונטי בפועל: זה קורה
  אך ורק בדפדפן שלך, על קובץ שאתה עצמך בחרת מהמחשב שלך.
- אין הגבלה חוקית/רגולטורית מובנית (כמו הסכמת נמען, שעות שליחה מותרות
  וכו') - האחריות על תוכן ואופן השימוש היא על המשתמש.
