# SMS Click Sender

אפליקציית ווב מקומית לשליחת SMS מותאם אישית לרשימת אנשי קשר, דרך טלפון
אנדרואיד המחובר בכבל USB. המערכת לא שולחת הודעות דרך שירות חוץ - היא שולטת
בטלפון עצמו (דרך ADB) כך שההודעות יוצאות מהמספר של הטלפון המחובר.

**איך זה עובד:** לכל איש קשר, המערכת פותחת את מסך כתיבת ה-SMS בטלפון עם
המספר וההודעה כבר ממולאים, מאתרת אוטומטית את כפתור "שלח" על המסך (על ידי
קריאת מבנה המסך בזמן אמת - לא קואורדינטות קבועות), ומדמה הקשה עליו.

מכיוון שזו אפליקציית ווב (Flask) ולא אפליקציית Desktop, **אותו קוד בדיוק
רץ גם על Windows וגם על שרת Linux** - ההבדל היחיד הוא איך פותחים אליה
דפדפן. פרק "הרצה על שרת Linux" למטה מפרט את זה.

## דרישות

- Python 3.9+
- טלפון אנדרואיד עם **ניפוי USB (USB Debugging)** מופעל (הגדרות → אודות
  הטלפון → הקש 7 פעמים על "מספר build" כדי לחשוף "אפשרויות למפתחים", ואז
  הפעל שם "ניפוי USB")
- כבל USB בין הטלפון למחשב/שרת
- Android Platform Tools (adb) מותקן

## התקנה - Windows

1. התקן Python מ-python.org (וודא לסמן "Add python to PATH" בהתקנה).
2. הורד את [Android Platform Tools ל-Windows](https://developer.android.com/tools/releases/platform-tools)
   וחלץ אותו לתיקייה, למשל `C:\platform-tools`. זה מכיל את `adb.exe`.
   ניתן להוסיף את התיקייה ל-PATH של Windows, **או** פשוט להזין את הנתיב
   המלא ל-`adb.exe` בשדה "נתיב adb" באפליקציה.
3. בתיקיית הפרויקט:
   ```
   pip install -r requirements.txt
   python app.py
   ```
4. חבר את הטלפון בכבל. במסך הטלפון תופיע בקשת אישור "לאפשר ניפוי USB?" -
   אשר אותה (ואפשר לסמן "אפשר תמיד ממחשב זה" כדי לא לחזור על זה בכל פעם).
5. פתח דפדפן בכתובת http://localhost:5000

## הרצה על שרת Linux

זו התוכנית המלאה להרצה כשרת - **בתנאי שהשרת הוא מכונה פיזית שאפשר לחבר
לה טלפון ב-USB בפועל** (מכונה וירטואלית בענן בלי USB passthrough לא
מתאימה לשיטה הזו, כי אין לה גישה חמרתית לפורט USB).

### 1. התקנת adb

Debian/Ubuntu:
```
sudo apt update && sudo apt install -y android-tools-adb android-tools-fastboot
```
Fedora/RHEL:
```
sudo dnf install -y android-tools
```

### 2. הרשאות USB בלי root

ברירת המחדל היא ש-adb צריך הרשאות root כדי לגשת להתקן USB. במקום להריץ
את כל השירות כ-root, נוסיף את המשתמש לקבוצה שמורשית לגשת להתקן, ונגדיר
udev rule:

```
sudo usermod -aG plugdev $USER
```
(יש להתנתק ולהתחבר מחדש, או להריץ `newgrp plugdev`, כדי שהשינוי יחול.)

צור קובץ `/etc/udev/rules.d/51-android-usb.rules` (יש דוגמה מוכנה
ב-`deploy/51-android-usb.rules` בפרויקט הזה - כולל הסבר איך למצוא את
מספר ה-Vendor ID של הטלפון עם `lsusb`), ואז:
```
sudo udevadm control --reload-rules && sudo udevadm trigger
```
נתק וחבר את הטלפון מחדש.

### 3. חיבור ואישור המכשיר

```
adb devices
```
בפעם הראשונה, בטלפון תופיע בקשת אישור "לאפשר ניפוי USB?" - יש לאשר אותה
פיזית פעם אחת על מסך הטלפון (חובה - זה צעד אבטחה של אנדרואיד שאין דרך
לעקוף מרחוק). מומלץ לסמן "אפשר תמיד ממחשב זה" כדי שהאישור יישאר גם אחרי
הפעלה מחדש של השרת.

### 4. השארת הטלפון פתוח וזמין

שיטת "סימולציית ההקשה" דורשת שהמסך של הטלפון יהיה **דלוק ולא נעול** בזמן
ריצת השליחה (אחרת ההקשות המדומות לא מגיעות לשום מקום). באפשרויות למפתחים
בטלפון:
- בטל נעילת מסך (או הגדר "ללא" בזמן שהטלפון מחובר לחשמל ב-USB)
- הפעל "הישאר פעיל" (Stay awake while charging)

ניתן גם להריץ בכל הפעלה של המחשב/שרת:
```
adb shell svc power stayon usb
```

### 5. התקנת האפליקציה כשירות (systemd)

```
sudo mkdir -p /opt/sms-click-sender
sudo cp -r . /opt/sms-click-sender
cd /opt/sms-click-sender
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

ערוך את `deploy/sms-click-sender.service` - שנה את `User=CHANGE_ME` למשתמש
הלינוקס שנמצא בקבוצת `plugdev` (מהשלב 2), ואז:

```
sudo cp deploy/sms-click-sender.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sms-click-sender
sudo systemctl status sms-click-sender
```

השירות ירים את השרת אוטומטית גם אחרי אתחול, ויפעיל אותו מחדש אם הוא קורס.

### 6. גישה לממשק

ה-Flask מוגדר כברירת מחדל להאזין רק על `127.0.0.1` (מהשרת עצמו), וזה
מומלץ כי **אין אימות משתמש/סיסמה מובנה באפליקציה** - מי שמגיע לממשק יכול
לשלוח הודעות SMS דרך הטלפון.

הדרך המומלצת לגשת מרחוק היא טאנל SSH:
```
ssh -L 5000:localhost:5000 USER@SERVER_IP
```
ואז פתיחת http://localhost:5000 בדפדפן במחשב שלך.

אם בכל זאת רוצים לגשת ישירות ברשת המקומית (LAN), אפשר לשנות ב-
`sms-click-sender.service` את `Environment=HOST=127.0.0.1` ל-
`Environment=HOST=0.0.0.0` - אבל **רק ברשת סגורה ובטוחה**, ורצוי להוסיף
מול זה שרת Nginx עם הרשאת Basic Auth כשכבת הגנה.

## שימוש באפליקציה

1. **חיבור הטלפון** - לחצו "בדוק מכשירים מחוברים" ובחרו את המכשיר מהרשימה.
2. **קובץ אנשי קשר** - העלו קובץ `.xlsx`/`.xls`/`.csv`. כל עמודה בקובץ
   (לדוגמה "שם", "טלפון", "עיר", "סכום"...) הופכת אוטומטית לפרמטר זמין.
   בחרו איזו עמודה היא מספר הטלפון (המערכת מנסה לנחש לפי שם העמודה).
3. **ההודעה** - כתבו את ההודעה, ולחצו על צ'יפים כמו `{שם}` כדי להוסיף
   פרמטר מכל עמודה בקובץ במקום הסמן.
4. **תצוגה מקדימה** - טבלה שמראה בדיוק מה יישלח לכל איש קשר (עד 20 שורות
   ראשונות), כולל אזהרה על פרמטר שלא קיים בקובץ (טעות הקלדה למשל).
5. **שליחה** - "מצב בדיקה" מסומן כברירת מחדל ומדמה את התהליך בלי לשלוח
   באמת - טוב לבדוק שהכל תקין. מבטלים את הסימון כדי לשלוח בפועל. יש
   הגבלת קצב (השהיה בין הודעות) כדי לא להעמיס על הטלפון ולא להיראות כספאם.

## מגבלות ידועות

- שיטת "סימולציית ההקשה" תלויה במסך שהמכשיר לא נעול. אם המכשיר ננעל
  באמצע ריצה, ההודעות הבאות לא יישלחו (יופיע כישלון בטבלת התוצאות).
- אפליקציות SMS שונות (Google Messages, Samsung Messages וכו') עלולות
  להיראות שונה על המסך; המערכת מנסה לאתר את כפתור "שלח" בכמה שיטות, ויש
  שדה "קואורדינטות גיבוי ידניות" בהגדרות המתקדמות למקרה שהאיתור האוטומטי
  נכשל על מכשיר/אפליקציה מסוימת.
- אין הגבלה חוקית/רגולטורית מובנית (כמו הסכמת נמען, שעות שליחה מותרות
  וכו') - האחריות על תוכן ואופן השימוש היא על המשתמש.
